# Code review, November 2026

A review of all of Explorer's own code (`src/`, not `vendor/`) for simplification, module organization and performance on hot paths. Performance findings are reasoned from the code, not measured.

Each step below is meant to be one commit. Tick a step off here in the commit that does it. Steps are ordered: the layering steps come first because they make every later move simpler.

## Target layout

Layers, bottom to top. A module imports only from its own layer or lower ones.

- **L0 `util/`**
  - `util/time.rs`: `civil_from_days`, `days_from_civil`, `local_offset_secs`, `format_log_time`, `now_secs`, `parse_utc_stamp`, `utc_stamp`, `utc_date`, `local_hhmm`.
  - `util/fs.rs`: `write_atomic`, `repo_hash`, `data_dir`, `config_dir`, `resolve_in` (today `agent::tools::resolve`).
  - `util/text.rs`: `word_bounds`, `drag_range`, `char_to_byte`, `single_line`, `key_values`, `split_metadata`.
  - `util/process.rs`: `kill_group`, `GroupGuard`.
- **L1 core data**: `git`, `loader`, `scan`, `markdown_format`, `config`, `conversation/`, `cli`, `highlight` (new: `TokenKind`, `ColoredSpan`, `ColoredLine`), `model_spec` (new: `ModelSpec`; the `*_KIND` consts moved to `config`), `usage` (moved from `agent/`).
- **L1 services**: `lsp/`, `watcher`. Neither imports `tui`.
- **L1 `signal.rs`**: `AppSignal`, `MainTx`, `send`/`try_send`, and the payloads `SymbolRefLocation`, `SymbolHighlight`, `FilesChanged` (today `BatchedWatchEvent`).
- **L2 `agent/`**: no `tui` or r3bl imports.
- **L3 `tui/`**
  - shell: `app/`, `state`, `focus` (new), `symbols` (new), `pane_manager`, `pane_component`, `panes_renderer`, `command_line`, `after_agents`, `theme`, `session`, `keymap`.
  - `tui/panes/`: `preview/`, `terminal/`, `git_log`, `commit_diff`, `conversation_tree/`, `discussion/`, `report`, `pickers/`.
  - `tui/widgets/`: `input_line`, `fuzzy_picker`, `fuzzy`, `title_row`, `text_layout`, `markdown`.
  - Panes never import `tui::app`. `tui/mod.rs` has no glob re-exports.

## Bugs found during the review

Fix these with the step that touches the code, or on their own first.

- [x] **B1. Dirty check runs on terminal output.** `app.rs:1717`: the "every ~5s" `git::is_dirty` walk counts `TerminalOutput` as well as the 1s `Noop` tick, so a busy terminal starts a worktree walk every 5 output chunks. Session save checks and LSP health checks (with a warn log) run at the same rate. Fix: only `Noop` runs the tick body; `TerminalOutput` only renders. Done: `Tick` (1s), `Housekeeping` (5s) and `UsagePollDue` (60s) signals replace the counters; `Redraw` replaces `Noop`; only `Tick` repaints (countdown, clock minute, a terminal pane with `flush_pending`, or an LSP restart that cleared colors); a file preview message expires through its own one-shot `Redraw`.
- [x] **B2. Work-log selection copies the wrong text while a turn runs.** `discussion_pane.rs:1451-1471` builds `src` offsets from `visible_work_log`, but `part_text` (`:658`) joins the full `work_log`. With dropped rounds hidden, a drag or copy in the work log selects different text than the one shown. Done: `DiscussionState.log_start` replaces `visible_work_log`; `shown_work_log()` feeds layout, `part_text` and the status line.
- [x] **B3. Thinking lines use the work log's marks.** `discussion_pane.rs:2040`: `DocPart::Thinking` is mapped to the work-log marks, so a work-log selection is painted on the thinking text and a thinking selection is never painted. Done: `Thinking` has its own marks.
- [x] **B4. LSP token scope fallbacks never run.** `theme.rs:70-85`: `color_for_scope` falls back to `ui.text`, so `color_for_lsp_token` always returns the first scope's lookup and never tries `keyword.control`, `namespace` and the other later scopes. Done: `HelixTheme::scope_fg` walks the dotted parents without the `ui.text` fallback, `color_for_scope` adds it on top, and `color_for_lsp_token` takes the first scope `scope_fg` styles. The scope list is most specific first (private theme names are split per token type: `parameter` → `variable.parameter`, `modifier` → `keyword.storage.modifier`, …).
- [x] **B5. Quitting during a commit turn claims the turn's commits were never made and throws them away.** `app.rs:2471`: the exit path marked a cut-short turn `Failed` when its reply was empty, even if it had committed; a live cancel (`turn.rs:549`) marks it `Cancelled` only when it also has commits, and the two rules had already drifted. Worse, quitting threw the commit list away: `meta.commits` stayed empty, so the tree hid a commit that exists and the next turn's repository-stayed note was computed from the wrong base. Done: `conversation::cut_short_outcome(reply, commits)` is the one rule, used by the exit path, the turn and `cancel_running_agents`; the exit path collects a commit turn's commits with `git::commits_since` from `TurnHandle.head_before` and records them, with `head_after` so a later turn derives its base from the right commit. `git::commits_since` replaces the two copies of the "HEAD did not move" test, and a test covers a commit turn cut short. The exit path still races the turn task's own closing (it writes the node before `TurnFinished` is handled, which never happens at exit): writing a shorter reply than the task flushes afterwards is accepted, quitting being a hard stop. Step 12 moved this into `ConversationTree::mark_cut_short` over `Metadata::mark_cut_short`, so the four fields travel together.
- [x] **B6. Closing a terminal behaves three ways.** `terminal_pane.rs:105-137`, `app.rs:362-388` and `close_window` (`app.rs:1950`) each close a terminal: only one sends focus-out, and `close_window` drops `terminal_to_preview` without restoring the preview. Done with step 7: every teardown goes through `focus::close_terminal`, which restores the preview an `e` terminal replaced, sends the focus-out through the PTY before dropping the pane, kills the child, and releases the keyboard whenever focus moved. A test covers the `<leader>x` path (`close_window` gives the preview back), and another the teardown itself.
- [x] **B7. Esc-close skips the focus notification** in `commit_diff_pane.rs:113`, `report_pane.rs:107` and `conversation_tree_pane.rs:1098`. The Discussion's `show` does not call `sync_terminal_grabbed`; the report's does. Done with step 7: all three close through `focus::close_window`, and the Discussion's `show` calls `focus::focus_window`, so the notification and the grab rule run wherever a window opens or closes.
- [x] **B8. The watcher ignores `target/` only at the top level.** `watcher.rs:155` checked the first path component; the loader walk prunes `IGNORED_DIRS` at every depth. Nested `foo/target/` build output became loaded files during a build. Done: `loader::is_ignored` checks every component and the watcher uses it; step 22 reuses it in the walk.
- [x] **B9. Fuzzy highlights drift on combining or ZWJ text.** The pickers built haystacks with `Utf32Str::new` (grapheme-indexed) but highlighted by `chars().enumerate()`. Done with step 20: `Query` reads a haystack as the text's chars and never as `Utf32Str::new`, which also means the pickers no longer index by byte on any text whose graphemes all start with an ASCII char — `"cafe\u{301} latte"` for `latte` used to report chars 7..11, which spell `atte`.
- [x] **B10. A panicking turn leaves its redraw ticker running.** `turn.rs`: `redraw.abort()` runs only after `TurnFinished` is sent. Done with step 15: the per-turn ticker no longer exists.

The ASCII fast path for `wrap`'s UAX-29 segmentation is the same: not on a per-frame path any more, and it needs a corpus-proved equivalent.
- Per-chunk work in `llm.rs` and the `claude -p` parser is small next to the render.
- `reply.md` is flushed at most once a second while streaming.
- The agent's grep and glob read from disk on purpose (fresh after its own writes).
- `local_offset_secs` per frame is cheap after glibc's first call.
- The window picker's per-frame list is O(window stack); its file match runs off-thread.
- The terminal render already groups cells into style runs.
- r3bl does not clone `AppState` per frame.
