# Code review, November 2026

A review of all of Explorer's own code (`src/`, not `vendor/`) for simplification, module organization and performance on hot paths. Performance findings are reasoned from the code, not measured.

Each step below is meant to be one commit. Tick a step off here in the commit that does it. Steps are ordered: the layering steps come first because they make every later move simpler.

## Target layout

Layers, bottom to top. A module imports only from its own layer or lower ones.

Fix these with the step that touches the code, or on their own first.

Ordered by expected gain.

- [x] **15. Streaming: fewer redraws.** Delete `Recorder::signal` and `PROGRESS_SIGNAL_INTERVAL`: the 100 ms ticker already redraws, so every streamed chunk adds up to 12 extra full renders a second. - [ ] **16. Streaming: the Discussion stops rebuilding the whole transcript every frame.** Add `LiveTurn.revision`, bumped by every mutation. The Discussion copies only on a new revision, and by appending (`work_log` is append-only). (Done with B2/B3: `log_start` and `shown_work_log()` replace `visible_work_log`, and Thinking has its own marks.) Still to do: the revision counter, the append-only copy, and one layout cache per part (prompt, thinking, work log appended entry by entry, reply). Also: a selection in progress points at other text when the shown work log changes (`log_start` moving, or the turn ending, mid-drag); clear the selection where `log_start` is synced (`discussion_pane.rs`, the sync near `log_start`). Later, if still needed: render only the reply after the last safe paragraph break (riskier: lists and fences across the cut).
- [x] **17. `display_width` fast path.** `text_layout.rs` built a `GCStringOwned` (a copy plus a segment vector) per call, and `wrap`, `truncate` and `wrap_spans` call it per word or per grapheme. Done: `display_width` returns `len()` for ASCII and sums `unicode_width` over graphemes otherwise (8x faster on the helper, measured against `GCStringOwned` for 16 samples in the tests); `truncate` slices ASCII instead of walking graphemes; `wrap` trims lines in place instead of allocating a second `String` per line; the two inline `GCStringOwned` measurements (status bar, centered commit-diff hint) call `display_width`; `text_layout` no longer imports `crate::tui::*`, and `unicode-width` is a direct dependency.
- [ ] **18. Conversation tree: build only the visible lines.** The render builds a `Line` with `truncate` for every node every frame (10 Hz while a turn runs), and `handle_input` rebuilds the rows on every event, running the nucleo filter 2-3 times per keystroke. Count lines without building them; build only `scroll..scroll+rows`. Then cache `(rows, matches)` on a `ConversationTree::revision` plus the fold state, query and queue length. Fold in, from step 17, since the same call sites are rewritten here:
  - `wrap` allocates one `String` per line by signature (`Vec<(usize, String)>`), for every node's title and summary, on every frame, including the rows that are never painted. Return each line's byte range into the text instead (`Vec<(usize, usize)>`) and let the caller slice; `truncate` gets the same treatment (a byte length rather than a `String`) for the rows that fit on one line. `Line.text` then becomes a `Cow<'_, str>`: borrowed from the node for titles and summaries, still owned for the agent titles and queued drafts that are built anyway. A painted row still builds its `InlineString` (`SmallString<[u8; 16]>`, so a short row does not reach the heap), but the rows above and below the viewport stop allocating. The signature change is compile-wide, so every other caller changes in the same commit: the four remaining `wrap` calls (`discussion_pane.rs:1420,1436,1456`, whose layout caching is step 16, and `markdown.rs:451` for code fences) and the seven `truncate` calls (`conversation_tree_pane.rs:1311,1329`, `discussion_pane.rs:2096,2151`, `report_pane.rs:212`, `command_line.rs:824`, `after_agents.rs:199`), of which only `discussion_pane.rs:2151` (a `Span`'s own `String`) and `after_agents.rs:199` (which appends `…`) still need to own the cut. The lines `wrap` returns are already trimmed, so the range is `start..start + trimmed_len`.
  - `wrap` runs full UAX-29 word segmentation (`split_word_bound_indices`) even for pure-ASCII paragraphs, and `markdown.rs`'s `split_words` (`wrap_spans`) walks every grapheme of every span to split on whitespace; on a 5 KB ASCII paragraph the segmentation costs about 47 us against about 3 us for a byte scan. A fast path is not a plain split on spaces: UAX-29 keeps `don't` and `1,000` whole but splits `a-b` and `word.`, so breaking would move around hyphens and punctuation. Tests must therefore compare the wrapped lines and their byte offsets against the UAX-29 path over a corpus of ASCII prose, URLs, paths and markdown, not the token lists.
- [ ] **19. Preview render: per-line overlays.** `preview.rs:792-940` runs the search regex, scans every symbol location of every file and walks chars from the line start once per wrapped sub-row. Compute the file's symbol ranges once per frame, the overlays once per line, and walk sub-rows with a running cursor. Keep the priority selection > search > symbol.
- [ ] **20. Fuzzy matching: one helper, scores only.** Five copies of the nucleo loop (git log filter, model, theme, window and ref pickers) → `widgets/fuzzy.rs` with `rank` (score only) and `match_indices` (for visible rows at render time, haystacks by chars, fixes B9). Also `paint_highlighted`: one paint op per style run instead of one `String` and op per char (`fuzzy_picker.rs:146`, `git_log_pane.rs:773`); borrow keys and positions instead of cloning them per row.
- [ ] **21. Removes `set_window_id`, `terminal_id`, `pane_height`, `active_commit`, `active_report`. About 80 lines.
- [ ] **22. Watcher batches: read files off the main thread, invalidate symbols in linear time.** `FileData::read` in the watcher worker; the main thread only swaps data. `apply_watch_batch` returns touched `FileKey` sets, so symbol invalidation stops being groups × locations × batch size (`app.rs:1153-1320`). - [ ] **23. Smaller per-frame and per-keystroke costs.**

  - Report pane: cache the rendered markdown by width instead of re-rendering every frame.
